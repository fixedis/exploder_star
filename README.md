# LEVIATHAN IMPACT — WebGL Cinematic Simulation

> Орбитальный таран планетарного ядра: космический левиафан пробивает спутник, тот раскалывается по всей тыльной стороне, и осколки — от каменной крошки до плит коры — падают на планету, оставляя на её поверхности кратеры, которые вращаются вместе с корой. Всё в одном HTML-файле, без зависимостей кроме CDN Three.js.

Чистый фронтенд-перформанс на **Three.js r160** + кастомные GLSL-шейдеры + постпроцессинг. Никакого физического движка — вся механика написана вручную.

---

## Что происходит на сцене

Таймлайн одного прогона, от тишины до пепла:

1. **Approach** — левиафан висит вдали, щупальца колышутся, камера свободна (WASD + мышь).
2. **Dive** — разгон по оси удара, slow-mo ×3, пульс bloom'а по нарастающей.
3. **Impact** — пробой спутника: вспышка, раскалывание тыльной полусферы на ~20 фрагментов рандомного размера, радиальный разлёт пояса астероидов от эпицентра.
4. **Cascade** — осколки тянутся к планете по гравитации; мелкие сгорают в атмосфере огненным росчерком, средние и плиты коры врезаются, оставляя кратер с чашей, валом и тлеющими разломами; над ударом поднимается гриб с потолком, чтобы не съесть атмосферу.
5. **Orbit** — медленное остывание шрамов, вращение планеты с кратерами на борту.

## Технический стек

| Слой | Технология |
|---|---|

## На чём считается физика

Коротко: **физика — на CPU (главный поток, JavaScript), пиксели — на GPU (шейдеры).** Физдвижка нет вообще.

**CPU (JS, один поток, эйлерова интеграция):**
- Гравитация `F = GM/r²` применяется к каждому летящему телу вручную: пояс астероидов, осколки коры, каменная крошка.
- Орбиты, столкновения с атмосферой, отскоки, затухание скорости — всё в циклах `for` по массивам.
- Пулы частиц — это не объекты, а параллельные `Float32Array` (`pos/vel/col/life/size`), курсор-кольцо, без аллокаций в кадре. Размеры пулов: трассы `80 000`, огонь `26 000`, дым `26 000`, черепки коры `18 000`, кратер `70 000`.
- Таймлайн удара, фронты выжигания, slow-mo (`timeScale`) — конечный автомат на JS.

**GPU (шейдеры, параллельно по пикселям/вершинам):**
- Процедурные биомы, лава, облака, выжженные шрамы, рваные края фронта — всё рисуется формулами в фрагментных шейдерах, без текстур.
- Изгиб тела левиафана и displacement поверхности — в вершинных шейдерах.
- Bloom, хроматическая аберрация, искажение ударной волной — полноэкранные проходы.

> То есть «тяжёлая» работа по пикселям лежит на видеокарте, а логика движения всех тел — на процессоре в одном потоке. Узкое место на слабом железе — именно CPU-циклы по частицам плюс fillrate постпроцесса.

## Потянут ли мобильные

Честный вердикт по классам устройств — проект тяжёлый, и вот почему:

| Устройство | Вердикт | Узкое место |
|---|---|---|
| Флагман (Snapdragon 8 / A16+) | ✅ Потянет, 30–60 fps | fillrate bloom'а |
| Средний смартфон | ⚠️ С просадками, 15–30 fps | CPU-циклы частиц + overdraw |
| Бюджетный / старый | ❌ Фриз/вылет | память пулов + fillrate |

Что именно давит на телефон:

- **Fillrate.** Bloom + 4 additive-слоя плёнки/зерна + аддитивные частицы = много проходов по каждому пикселю. Мобильные GPU это не любят.
- **Частицы.** Суммарно ~200k частиц в пулах — это CPU-работа каждый кадр.
- **Тени.** `shadowMap` 2048×2048 — дорого на мобиле.
- **pixelRatio cap = 2** — на ретине это ×4 пикселей, для слабого GPU убийственно.

**Рубильники для слабого железа** (крутить по одному, пока не пойдёт плавно):

```js
renderer.setPixelRatio(1);                 // самый сильный выигрыш
renderer.shadowMap.enabled = false;        // убрать тени
// в composer: убрать bloom-пасс и shockPass — оставить Render+Output
// уменьшить пулы: P=20000, firePool/smokePool=8000, craterPool=20000
```

На десктопе всё это трогать не нужно — там запас огромный.

## Управление

| Клавиша / действие | Эффект |
|---|---|
| `W A S D` | Полёт камеры вдоль взгляда |
| `Q` / `E` | Вниз / вверх |
| `Shift` | Форсаж (×3 скорости полёта) |
| Мышь (ЛКМ / ПКМ / колесо) | Обзор / панорама / зум |
| `V` | Отладочные метки эпицентров на планете |
| Кнопки | AUTO ORBIT · INITIATE IMPACT · TENSION FX · RESET |

> Камера и тряска считаются в реальном времени и **не** замедляются slow-mo — летать удобно даже во время рапида.

## Архитектура (один файл, модули-классы)

Логика разбита на изолированные блоки-«модули», каждый со своей зоной ответственности:

- **NoiseLib** — GLSL+JS шум (simplex, fbm, worley, crater).
- **Сцена/камера/постпроцесс** — рендерер, composer, шейдер удара.
- **Земля / Облака / Атмосфера** — три шейдерных сферы, шрамы в локальной системе координат (вращаются с корой).
- **Спутник** — патчи коры, откол тыльной полусферы.
- **Левиафан** — группа мешей + процедурный изгиб + щупальца.
- **Пулы частиц** — огонь / дым / черепки / кратер / трассы.
- **Система ударов** — конечный автомат вспышка → кольцо → гриб → шрам.
- **Камера + UI** — WASD, HUD, кнопки.

## Ручки тюнинга (одна правка — один эффект)

| Что крутим | Где | Параметр |
|---|---|---|
| Минимум читаемого ожога | `spawnImpact` | `lerpK(0.12, 0.45, im.mag)` |
| Потолок гриба (чтоб не ел атмосферу) | `updateImpacts` | `PLANET_R*0.32` / `*0.42` |
| Калибр взрыва гиганта | `launchCrustCluster` | `320+rand*140` |
| Скорость гиганта (прилёт последним) | `launchCrustCluster` | `170+rand*40` |
| Число отколов / порог полусферы | блок `antipodePatches` | `TAKE=20`, порог `0.02` |
| Сила slow-mo | константа | `SLOWMO = 1/3` |

```bash
python -m http.server 8000
# открыть http://localhost:8000/
```
